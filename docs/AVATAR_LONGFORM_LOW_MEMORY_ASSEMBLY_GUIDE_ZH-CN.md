# 数字人长视频切割与交接：低内存稳定化指导文档

**任务类型：** 单次稳定性优化  
**适用范围：** 数字人口播项目的“每位角色一条长视频”导入模式  
**不在范围内：** 改写脚本、重新 ASR、重新审核切点、替换数字人原片、改变画面生成策略

## 1. 问题与结论

当前实现会在一个 FFmpeg 滤镜图中同时打开长视频源，并为所有台词轮次建立并行的裁切、缩放、补边和拼接分支。对 1080p HEVC 长视频而言，这会累积解码帧和滤镜缓存；在可用内存有限时，最终会出现 `Cannot allocate memory`，前端则只停在“正在进入片段工作台”的过渡状态。

已确认本期两条原片能够独立完整解码，问题不是上传损坏，而是一次性并行合成的资源模型不适合长视频工作流。

## 2. 本次交付目标

1. 将长视频合成改为 **按 T001、T002… 串行处理**。
2. 每段先转为统一规格的中间片段：项目画幅、H.264、AAC、固定帧率。
3. 中间片段按输入签名复用；中断或失败后重试时跳过已完成且仍有效的片段。
4. 最后用单路串行拼接生成数字人原声母版，避免同时展开全部轮次。
5. 在素材页显示阶段、当前轮次、完成数、复用数和失败原因；失败后可安全重试。
6. 保持台词切点、原片、ASR 结果与用户选择的出镜方式不变。

## 3. 实现策略

### 3.1 两阶段合成

```text
已审核长视频切点
  -> 单段规范化（每次只处理一个 Txxx）
  -> 可复用中间片段目录
  -> 单路顺序拼接
  -> 母版 QA
  -> 应用真实时间线 / 进入片段工作台
```

每段处理只打开一个输入视频，并限制解码、滤镜和编码线程。原片为非标准画幅时，继续沿用用户选定的“模糊背景 / 黑边完整显示 / 裁切铺满”规则。

### 3.2 断点恢复合同

- 中间片段的签名由源文件指纹、切点、间隔、项目画幅、帧率、音频采样率和画幅处理方式组成。
- 同签名且通过媒体检查的片段可复用。
- 单段失败时，不删除此前完成的片段；重试从失败段继续。
- 用户在处理中修改切点、上传替代原片或改画幅规则时，签名改变，旧片段自动失效且不会被错误复用。

### 3.3 前端状态

素材页的“生产闸门”必须区分：

- `正在规范化 T006（5/14）`
- `正在拼接 14 个已规范化片段`
- `合成失败：T006 …；已保留 5 个可复用片段`
- `可重试：无需重新上传或重新审核`

点击“一键进入片段工作台”后，页面刷新或返回数字人素材页都应能读取同一状态，而不是视觉上无限等待。

## 4. 优先级与具体改动

| 优先级 | 改动 | 验收标准 |
|---|---|---|
| P0 | 长视频串行裁切与拼接 | 不再构建 14 路并行滤镜图；同一时刻只处理一个源片段 |
| P0 | 进度持久化与可恢复中间片段 | 服务重启或一次失败后，重新执行会复用有效已完成段 |
| P0 | 正确失败反馈 | 前端能显示失败阶段、轮次、已完成数和重试提示 |
| P1 | 低资源参数 | 固定线程上限，输出 H.264/AAC、固定项目画幅和帧率 |
| P1 | 自动化测试 | 覆盖串行路径、复用路径、单段失败保留结果、原有逐段导入路径 |
| P2 | 当前项目真实验收 | 使用本期雅雅、檬檬原片生成母版并验证可进入片段工作台 |

## 5. 风险控制

- 不删除原始长视频，不重置已批准的切点。
- 中间片段写入候选文件后原子替换，避免留下半成品被误用。
- 如果最终拼接失败，保留中间片段，状态明确为失败且允许重试。
- 最终母版仍做可解码性、时长、H.264/AAC 与原生音频 QA。
