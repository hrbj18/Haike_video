# OpenMontage 数字人口播工作流优化实施与交付指导

> 文档状态：P0 已实现，保留后续迭代边界
> 适用范围：`avatar-spokesperson` 数字人口播工作流
> 优先实现路径：本地导入数字人视频，云端生成作为可插拔能力
> 关联文档：`docs/PRD_VIDEO_WORKBENCH_ZH-CN.md`、`docs/AVATAR_PODCAST_IMPORT_ZH-CN.md`
> 最后更新：2026-08-11

## 1. 文档目的

本文档用于在数字人口播工作流正式开发前冻结需求边界、产品术语、数据合同、状态流转、媒体规则、增量渲染策略和验收标准。

本文档不是新的总 PRD，也不取代现有视频工作台 PRD。它是数字人口播能力的专项实施指导，负责回答以下问题：

1. 数字人口播与普通素材讲解的根本区别是什么；
2. 外部平台生成并下载的数字人视频应以什么身份进入 OpenMontage；
3. 全屏数字人、画中画讲解员和主体素材之间如何组合；
4. 数字人视频、输入音频、脚本估算时长中，谁拥有最终时间轴；
5. 如何让单个数字人片段可以独立返工，而不重新生成整条视频；
6. 前端应该展示哪些步骤、状态、反馈和审核操作；
7. 第一版必须实现什么，哪些能力明确延期；
8. 如何测试并证明该工作流可靠、可追溯、可局部替换。

除非后续形成新的明确产品决策，本文件中的“必须”“禁止”“P0”均视为开发约束。

## 2. 已验证事实与现状

### 2.1 已验证的阿里云数字人链路

此前已经通过阿里百炼完成以下最小链路验证：

```text
人物图片
  -> wan2.2-s2v-detect
  -> 输入音频
  -> wan2.2-s2v
  -> 有声数字人 MP4
```

测试结果证明数字人生成链路可用，但同时证明了一个关键事实：

- 输入音频约为 7.083 秒；
- 数字人输出视频约为 6.875 秒；
- 输出视频内嵌音频约为 6.842 秒；
- 服务端可能裁切首尾、重新编码或改变实际媒体边界。

因此，输入音频只能作为生成输入，不能作为最终剪辑时间轴。

### 2.2 当前项目已有能力

项目当前已经具备以下基础：

- `avatar-spokesperson` 正式工作流清单；
- 供应商无关的 `avatar_source_package` 数据合同；
- 按轮次逐条导入与长视频兼容导入；
- 本地视频上传、路径约束、SHA-256 和媒体探测；
- 视频流、音频流、分辨率、帧率、采样率和时长检查；
- ASR 台词核验；
- 数字人原声母版、时间线、字幕和 QA 文件生成；
- 原生数字人音频阻止重复生成 TTS；
- 基础素材台账、场景审核和片段版本机制。

### 2.3 当前主要缺口

当前已有“数字人素材导入器”，但尚未形成完整的“数字人口播生产工作流”。主要缺口包括：

- 新建项目页面没有暴露数字人口播工作流；
- 新数字人项目无法从前端自然进入素材包初始化流程；
- 工作流、素材来源和画面版式概念混杂；
- 只有数字人母版拼接，没有“数字人 + 主体画面”的场景级合成；
- 没有全屏、画中画、暂时隐藏等场景版式合同；
- 数字人片段尚未完整接入场景审核与局部候选晋级；
- 缺少数字人口播专属的音频重复保护、遮挡检查和画幅安全区；
- 长任务缺少统一的运行编号、修订号和过期结果拦截。

## 3. 核心产品判断

### 3.1 数字人是“演员素材”，不是最终成片

从外部平台下载的数字人视频应被视为一种带原生声音的演员素材。OpenMontage 负责：

- 登记和验证数字人素材；
- 读取真实音频时长；
- 建立脚本轮次和实际媒体的对应关系；
- 决定数字人在每个场景中的版式；
- 搜集并管理主体画面；
- 合成字幕、图文、背景音乐和最终视频；
- 支持逐段审核、局部替换、回滚和交付。

### 3.2 本地导入是 P0，云端生成是供应商插件

第一版以用户从其他平台生成、下载并上传数字人视频为主路径。

阿里百炼、Kling、HeyGen 或未来其他数字人服务，不得将供应商字段直接扩散到工作台状态和场景模型中。所有提供方最终都必须输出相同的数字人素材合同。

```text
手工下载上传 ─┐
阿里云生成   ─┼─> avatar_source_package ─> 统一验证、审核和合成
其他 API     ─┘
```

### 3.3 工作流、来源和版式必须分离

| 维度 | 含义 | 示例 |
|---|---|---|
| 主制作方式 | 视频采用什么叙事与生产语法 | 素材讲解、数字人口播、屏幕演示、电影感叙事 |
| 素材来源 | 具体素材从哪里获得 | 人工提供、网络下载、AI 生成、项目素材库、云端数字人 |
| 数字人版式 | 数字人在某个场景中如何出现 | 全屏、画中画、暂时隐藏、透明人物 |

禁止将“混合素材”“本地导入”“左上角数字人”作为同一层级的工作流选项。

### 3.4 项目提供默认版式，场景允许覆盖

项目可以设置默认数字人版式，但每个场景必须可以单独覆盖。

推荐结构：

```text
项目默认：画中画 / 左上角

场景 01：数字人全屏
场景 02：数字人左上角，主体画面展示资料
场景 03：暂时隐藏数字人，主体素材全屏，保留数字人原声
场景 04：数字人全屏收束
```

## 4. 不可违反的媒体与时间轴规则

### 4.1 时间轴主时钟

数字人口播项目的最终时间轴主时钟为：

```text
通过媒体探测验证后的数字人输出文件内嵌音频
```

优先级如下：

```text
数字人输出内嵌音频时长
  > 数字人视频容器总时长
  > 原始输入音频时长
  > 脚本估算时长
  > 项目创建时填写的目标时长
```

项目目标时长只用于脚本规划和预算提示，不能用于拉伸数字人音频或嘴型视频。

### 4.2 禁止拉伸数字人语音和嘴型

禁止通过以下方式强行匹配脚本计划时长：

- 对数字人音频执行时间拉伸；
- 改变数字人视频播放速度以追赶旧时间线；
- 用长时间末帧冻结冒充正常口播；
- 将原始输入音频重新覆盖到已经生成的数字人视频上；
- 在数字人视频自带声音的同时再次叠加 Voicebox TTS。

### 4.3 音频分层

合成阶段必须显式拆分媒体职责：

| 层 | 规则 |
|---|---|
| 数字人画面 | 合成时静音，避免内嵌音频被重复播放 |
| 数字人主音轨 | 从已验证数字人文件中提取，作为唯一对白主音轨 |
| 主体素材原声 | 默认静音；只有明确批准后才保留 |
| 背景音乐 | 独立音轨，自动避让对白 |
| 环境音效 | 独立登记、独立使用编号、独立混音 |

### 4.4 实际时长变化

局部替换数字人片段后，如果新片段时长变化：

- 新片段使用自己的自然时长；
- 后续片段开始时间允许顺延或提前；
- 后续片段的媒体内容、版本和渲染文件保持不变；
- 只更新最终编辑决策列表、时间坐标和拼接结果；
- 前端必须在采用候选前展示时长影响。

这称为“内容冻结、时间位置可顺延”。不得声称后续片段时间坐标也完全冻结。

## 5. 第一版范围

### 5.1 P0 必须实现

- 单数字人项目；
- 本地手工导入；
- 按脚本轮次逐段上传，长视频仅作兼容模式；
- H.264/AAC MP4 基线输入；
- 横版 16:9 与竖版 9:16；
- 数字人全屏；
- 矩形画中画；
- 画中画四角位置，左上角为产品默认值；
- 项目默认版式与场景级覆盖；
- 数字人原声音频时间线；
- Pexels、AI 生成、人工提供和项目素材库作为主体画面来源；
- 场景级组合预览；
- 单段数字人替换；
- 单段主体素材替换；
- 单段字幕审核；
- 候选、采用、回滚和局部合成；
- 全流程中文状态和错误信息；
- 任务进度、等待、失败、重试和过期状态反馈。

### 5.2 P1 建议实现

- 长视频 ASR 切分兼容模式完善；
- 画中画边框、圆角、阴影和背景板样式；
- 自动字幕避让；
- 数字人脸部裁切和黑边检查；
- 主体素材遮挡风险提示；
- 背景音乐和环境声精细混音；
- 生成多个画幅版本；
- 阿里百炼数字人适配器；
- 自动生成数字人导出任务清单和推荐文件名。

### 5.3 本轮明确不实现

- 无背景透明人物自动生成；
- 任意普通 MP4 的高质量自动抠像；
- 复杂绿幕溢色修复；
- 多数字人自由对话编排；
- 数字人手势重定向；
- 逐帧嘴型手工调整；
- 传统 NLE 式轨道拖拽；
- 项目创建时暴露供应商内部参数；
- 为满足旧时间线而拉伸语音或数字人视频。

透明 WebM、ProRes 4444 和绿幕抠像可以作为后续高级输入能力，但不能阻塞第一版交付。

## 6. 用户端完整流程

### 阶段 A：创建数字人口播项目

用户在新建项目中选择“数字人口播”。

创建页保留公共字段：

- 项目名称；
- 项目代号；
- 目标时长；
- 画幅；
- 内容目标或简要脚本。

选择数字人口播后，动态显示以下信息：

- 是否已有脚本：已有完整脚本 / 只有想法 / 从零开始；
- 数字人素材来源：本地导入 / 云端生成；
- 素材导出方式：逐段视频 / 一条长视频；
- 默认版式：全屏 / 画中画；
- 是否需要主体辅助画面。

第一版默认值：

```yaml
pipeline_type: avatar-spokesperson
avatar_source_mode: manual_import
avatar_import_mode: per_turn
default_presenter_layout: picture_in_picture
default_pip_position: top_left
supporting_visuals: true
audio_authority: embedded_avatar_audio
```

创建页不要求填写数字人供应商模型、透明通道参数、FFmpeg 参数或渲染引擎内部配置。

### 阶段 B：脚本准备

数字人口播脚本必须满足口语表达和局部替换要求：

- 每个轮次表达一个完整意思；
- 每个轮次建议 5 至 20 秒；
- 不在一个轮次中塞入多个视觉主题；
- 句尾完整，避免在连接词或呼吸中切段；
- 每个轮次拥有稳定 `turn_id`；
- 每个轮次拥有说话人、台词和推荐文件名；
- 每个轮次可以声明主体画面意图。

推荐文件名：

```text
T001_YAYA.mp4
T002_YAYA.mp4
T003_YAYA.mp4
```

脚本批准后才能初始化数字人素材包。修改已批准脚本时，必须明确提示哪些轮次素材会失效。

### 阶段 C：数字人素材导入

前端必须支持：

- 批量拖入；
- 逐条选择；
- 按 `Txxx` 自动归位；
- 上传进度；
- 单条失败不影响其他条目；
- 重名、重复内容和未知编号提示；
- 替换已有轮次文件；
- 查看媒体探测结果；
- 查看 ASR 文本和相似度；
- 播放单条数字人视频；
- 单独试听该条原声音频。

### 阶段 D：真实时间线提交

所有必需片段通过媒体检查与台词核验后，系统提交数字人真实时间线：

```text
T001 实际原声音频
  -> T002 实际原声音频
  -> T003 实际原声音频
  -> 项目真实总时长
```

提交后生成：

- 轮次时间线 JSON；
- 项目主音轨；
- 逐句字幕；
- 场景与渲染片段基线；
- 需要主体素材的场景清单。

### 阶段 E：场景版式与主体素材

每个场景必须显示：

- 数字人片段；
- 实际时长；
- 当前版式；
- 主体素材来源；
- 首帧和高潮帧；
- 字幕预览；
- 画中画位置；
- 当前审核状态。

每个场景允许选择：

1. 数字人全屏；
2. 数字人画中画；
3. 暂时隐藏数字人，仅保留原声与主体画面。

“透明人物”可以进入数据合同，但第一版前端不提供该选项。

### 阶段 F：场景审核

用户审核的是组合结果，而不是孤立素材。最小审核单元应同时包含：

- 数字人画面；
- 主体画面；
- 原声；
- 字幕；
- 场景头尾边界。

必须提供：

- 播放本场景；
- 只试听原声；
- 替换数字人片段；
- 一键更换主体素材；
- 切换全屏/画中画/隐藏；
- 调整画中画角落和预设尺寸；
- 编辑字幕文本，但不手工拖字幕时间；
- 标记通过；
- 标记需要调整；
- 查看候选与当前版本差异。

### 阶段 G：成片与局部返工

全部场景通过后允许合成完整成片。

任何单段修改均走候选流程：

```text
创建候选
  -> 上传或选择新素材
  -> 媒体检查
  -> 台词核验
  -> 计算时长影响
  -> 局部组合预览
  -> 用户采用
  -> 只重合成目标片段
  -> 原子并入成片
```

失败候选不得覆盖当前版本。

## 7. 前端信息架构

数字人口播工作流建议只保留五个一级页面：

| 页面 | 责任 |
|---|---|
| 总览 | 展示当前阶段、缺失输入、阻塞项和下一步 |
| 脚本 | 编写、拆分和批准数字人口播轮次 |
| 数字人素材 | 上传、探测、核词、试听和建立真实时间线 |
| 场景审核 | 审核数字人、主体画面、字幕和局部候选 |
| 成片与版本 | 完整合成、候选晋级、回滚和交付 |

“素材库”仍然存在，但主体素材优先从场景审核页直接选择和替换，不要求用户为了更换一段画面来回切换页面。

### 7.1 导航显示规则

- `pipeline_type == avatar-spokesperson` 时，“数字人素材”入口必须始终显示；
- 尚未批准脚本时，数字人素材页显示阻塞原因和“返回脚本”按钮；
- 尚未初始化素材包时，页面显示初始化向导；
- 不能依赖 `avatar_package` 已存在才显示入口；
- 非数字人项目不显示数字人专属导航；
- 当前步骤、已完成步骤和阻塞步骤必须可视化。

### 7.2 长任务反馈

上传、ASR、局部合成和完整合成都必须显示：

- 正在执行的任务名称；
- 已完成数量 / 总数量；
- 当前轮次；
- 已运行时间；
- 是否可以安全离开页面；
- 失败原因；
- 重试按钮；
- 任务完成后的下一步。

禁止用户点击后界面没有反馈。

### 7.3 无障碍与错误恢复

- 动态表单字段出现时使用可感知的状态提示；
- 状态变化通过 `aria-live` 宣告；
- 所有按钮均使用明确中文动作名称；
- 关闭和取消不得触发表单必填校验；
- 上传失败后保留已成功条目；
- 键盘可以完成选择、上传、播放和确认；
- 不只依赖颜色表达通过、失败和运行中。

## 8. 数据模型指导

### 8.1 项目创建信息

`project.json.intake` 建议增加数字人专项配置：

```json
{
  "avatar": {
    "source_mode": "manual_import",
    "import_mode": "per_turn",
    "default_layout": "picture_in_picture",
    "default_pip_position": "top_left",
    "supporting_visuals": true,
    "audio_authority": "embedded_avatar_audio"
  }
}
```

这些字段属于制作决策，不属于供应商参数。

### 8.2 数字人素材包

现有 `avatar_source_package` 继续作为供应商无关合同。建议扩展：

```json
{
  "audio_mode": "native_avatar_audio",
  "provider": {
    "type": "manual_import",
    "name": "ManualAvatarImportProvider"
  },
  "media_contract": {
    "background_mode": "baked",
    "alpha_mode": "none",
    "expected_audio": "embedded"
  }
}
```

建议值：

- `background_mode`: `baked`、`transparent`、`green_screen`；
- `alpha_mode`: `none`、`straight`、`premultiplied`、`unknown`；
- `expected_audio`: `embedded`、`separate`。

第一版只承诺完整支持：

```text
background_mode = baked
alpha_mode = none
expected_audio = embedded
```

### 8.3 场景数字人版式

`scene_plan` 或数字人专项场景合同应保存：

```json
{
  "presenter_treatment": {
    "mode": "picture_in_picture",
    "position": "top_left",
    "scale": 0.28,
    "margin_x": 32,
    "margin_y": 32,
    "frame_style": "soft_card",
    "safe_area_policy": "avoid_captions"
  }
}
```

允许模式：

- `fullscreen`；
- `picture_in_picture`；
- `hidden`；
- `cutout`，仅预留，第一版不开放。

### 8.4 状态轴分离

不要把所有状态压进一个 `status` 字段。每个轮次至少分为：

```json
{
  "import_status": "media_valid",
  "transcript_status": "passed",
  "review_status": "approved",
  "render_status": "current"
}
```

这样可以避免“文件已上传但未核词”和“文件已核词但组合画面未通过”被误认为同一个状态。

### 8.5 素材编号与使用编号

继续沿用总 PRD 的统一编号体系：

- 数字人源文件获得稳定素材编号 `S-xxx`；
- 某场景使用该素材时获得使用编号 `U-xxx`；
- 同一数字人源文件可以被多个场景复用；
- 裁切、缩放、位置、边框和静音属于 `U-xxx` 使用变换；
- 替换源文件产生新的素材版本，不得静默覆盖旧版本；
- `Txxx` 是脚本轮次，不替代素材身份。

## 9. 合成架构

### 9.1 场景层级

```text
场景画布
├─ 主体画面层：Pexels / AI / 人工 / 项目素材
├─ 数字人画面层：全屏 / 画中画 / 隐藏
├─ 图文层：标题、重点词、Logo、提示卡
├─ 字幕层：逐句字幕与安全区
└─ 音频层
   ├─ 数字人原声主音轨
   ├─ 背景音乐
   └─ 已批准的环境音
```

### 9.2 全屏模式

- 数字人画面填充画布；
- 默认使用 `contain`，不得非等比拉伸；
- 允许背景色或模糊扩展填补比例差异；
- 不允许裁掉人脸和主要手势；
- 字幕必须避开人物嘴部和关键手势区域；
- 支体素材仅作为短暂切出或图文覆盖。

### 9.3 画中画模式

- 主体素材填充画布；
- 数字人作为独立矩形卡片叠加；
- 默认位置左上角；
- 必须支持左上、右上、左下、右下；
- 画中画默认宽度：横版 22% 至 28%，竖版 26% 至 34%；
- 字幕优先放在下方安全区；
- 主体素材的搜索提示词应包含数字人占位安全区要求；
- 普通 MP4 的背景会保留在卡片内，不得伪装为透明人物。

### 9.4 暂时隐藏模式

- 数字人画面不可见；
- 数字人原声继续播放；
- 主体素材全屏；
- 适合数据、步骤、书页、产品演示和案例画面；
- 恢复数字人时应在自然语义边界切换。

### 9.5 渲染运行时

数据合同必须保持运行时无关。具体项目在方案阶段按照 OpenMontage 决策合同选择并锁定运行时。

- FFmpeg：负责可靠的基础全屏、画中画、音频提取、字幕和局部拼接；
- Remotion：适合更丰富的图文、响应式版式和数字人卡片动画；
- HyperFrames：适合设计驱动的动态图形与网页式动画组合；
- 运行时不可在合成阶段静默替换；
- 无论选择哪种运行时，都必须满足相同的时间轴和增量渲染合同。

## 10. 局部热插拔合同

### 10.1 片段所有权

每个数字人轮次映射到一个可替换渲染片段：

```text
T002
  -> 数字人素材 S-012 / 使用 U-031
  -> 主体素材 S-020 / 使用 U-032
  -> 字幕版本
  -> SEG-002
```

### 10.2 候选生成

创建候选时必须记录：

- 基础项目修订号；
- 基础轮次修订号；
- 当前片段版本；
- 新数字人素材或新主体素材；
- 新实际时长；
- 对后续片段开始时间的影响；
- 需要重新合成的文件列表；
- 必须保持不变的片段哈希。

### 10.3 两阶段提交

第一阶段只生成候选和局部预览，不改变当前成片。

第二阶段只有用户点击“采用候选”后才执行：

1. 验证基础修订号仍然有效；
2. 验证 A、C 片段文件哈希未变化；
3. 原子更新 B 的当前版本指针；
4. 更新后续时间坐标；
5. 重新拼接最终成片；
6. 写入审计记录；
7. 保留旧成片和回滚指针。

### 10.4 并发与过期结果保护

所有异步任务必须携带：

```text
job_id
project_revision
turn_revision
started_at
status
superseded_by
```

任务完成时，如果项目或轮次修订号已经变化，结果只能标记为 `superseded`，不得提交到当前版本。

同一轮次同一任务类别在任一时刻只允许一个可提交任务。全局合成与局部合成不得同时写入同一个当前版本指针。

### 11.1 手工导入提供方

ManualAvatarImportProvider

- 云端失败不得自动切换到其他付费供应商；
- 供应商切换必须向用户说明并获得确认；
- 下载 URL 可能过期，正式合成必须优先使用本地冻结文件。

## 15. 验收标准

### AC-AV-001 创建入口

用户可以从项目库选择“数字人口播”，创建后进入正确的工作台，不出现原始 pipeline ID 或英文状态。

### AC-AV-002 工作流输入要求

选择数字人口播后，页面展示脚本状态、数字人来源、导入粒度、默认版式和主体辅助画面选项。

### AC-AV-003 前端从零操作

用户无需手工创建目录或 JSON，即可完成素材包初始化、上传、核词、时间线提交和合成。

### AC-AV-004 原声时间轴

项目最终时长来自数字人输出文件内嵌音频，不使用脚本估算或原输入音频覆盖。

### AC-AV-005 无语音拉伸

任何生成、局部替换和完整合成都不会对数字人语音或嘴型视频进行时间拉伸。

### AC-AV-006 音轨唯一性

最终成片只能存在一份对白主音轨，不出现数字人原声和重复 TTS 同时播放。

### AC-AV-007 三种场景版式

场景可选择全屏、画中画或隐藏数字人，且组合预览与成片一致。

### AC-AV-008 多来源主体画面

画中画或隐藏模式可使用网络下载、AI 生成、人工提供和项目素材库。

### AC-AV-009 场景级审核

用户可以在一个场景页面同时审核数字人、主体画面、字幕、原声和场景边界。

### AC-AV-010 局部数字人替换

替换某轮次数字人后，系统生成候选，展示实际时长变化，并只重合成目标片段。

### AC-AV-011 冻结证明

在三段视频只修改第二段的测试中，第一、第三段渲染文件哈希保持不变。

### AC-AV-012 时长顺延

第二段时长变化后，第三段内容不重渲染，但其最终开始时间按照新时间线更新。

### AC-AV-013 失败不污染当前版本

上传、ASR、局部合成或完整合成失败时，当前成片和已批准片段保持可播放。

### AC-AV-014 并发安全

旧任务晚于新任务完成时，只能标记为过期，不得覆盖新任务结果。

### AC-AV-015 比例正确

横版、竖版和不同来源比例的数字人及主体素材均不发生非等比拉伸。

### AC-AV-016 完整中文反馈

所有用户可见的按钮、状态、错误、重试和空状态均使用统一中文术语。

## 16. 兼容与迁移

### 16.1 旧数字人素材包

- 新增字段必须有安全默认值；
- 缺少版式字段时默认 `fullscreen`；
- 缺少媒体背景字段时默认 `background_mode = baked`；
- 缺少独立状态轴时从旧 `status` 推导；
- 不修改原始媒体文件；
- 迁移写入前保留旧合同副本或修订记录。

### 16.2 普通视频项目

- 普通素材讲解项目不自动增加数字人导航；
- 现有 Voicebox 音频优先流程保持不变；
- 新增字段均限制在数字人口播工作流；
- 通用素材编号、场景审核和热插拔能力继续复用。

### 16.3 当前总 PRD 的冲突处理

数字人口播对总 PRD 的“冻结”作如下精确定义：

- 冻结的是片段内容、素材版本、字幕版本和渲染文件；
- 当自然音频时长变化时，后续片段的时间坐标允许变化；
- 不允许为了保持旧坐标而拉伸数字人语音；
- A/C 无需重新渲染，但最终拼接清单需要更新；
- 场景审核负责判断当前组合是否合格；
- 热插拔负责生成、验证和晋级替换候选；
- 两者使用相同场景入口，但状态和操作职责不同。

## 18. 开发完成定义

只有同时满足以下条件，数字人口播第一版才算完成：

1. 用户能完全通过前端创建数字人口播项目；
2. 用户能从想法或现有文本获得分段脚本；
3. 用户能逐段上传数字人视频并看到明确进度；
4. 系统以数字人内嵌音频建立真实时间线；
5. 用户能为每个场景选择全屏、画中画或隐藏；
6. 用户能为需要的场景选择多来源主体素材；
7. 用户能在场景中试听原声、查看字幕并审核组合结果；
8. 用户能一键生成完整成片；
9. 用户能只替换某一个数字人片段；
10. 局部替换失败不会污染当前版本；
11. A/C 冻结可通过文件哈希证明；
12. 前端没有无反馈按钮、英文错误或无法退出的弹窗；
13. 自动化测试、媒体测试和真实浏览器流程测试全部通过；
14. 实现与本文档、总 PRD、数据 schema 和管线指导保持一致。

## 19. 最终决策摘要

本轮优化按照以下顺序推进：

```text
数字人口播项目入口
  -> 分段口播脚本
  -> 本地逐段数字人导入
  -> 媒体与台词核验
  -> 数字人原声真实时间线
  -> 全屏 / 画中画 / 隐藏
  -> 多来源主体画面
  -> 场景组合审核
  -> 完整合成
  -> 局部数字人或主体素材热插拔
  -> 可证明的冻结、回滚与交付
```

第一版的价值不在于数字人供应商数量，而在于建立一条稳定、可审核、可局部返工、不会重复音轨、不会拉伸语音、完全可从前端操作的数字人口播生产线。

## 20. 本次实现交付状态（2026-08-11）

### 20.1 已完成并已自动验证

- 项目库可直接选择“数字人口播（导入本地数字人视频）”；工作台在素材包初始化前也显示“数字人素材”入口；
- 数字人项目不会进入通用 Voicebox 项目旁白或片段 TTS 路径；后端同样拒绝通过接口绕过此限制；
- 用户可在前端建立导入合同，明确逐轮次/长视频模式、原片背景类型与默认出镜方式；
- 合成通过后，“应用为真实时间线”会把数字人母版复制为项目内不可变版本，登记稳定 `S-xxx` 身份和每场景 `U-xxx` presenter 使用记录；
- 每个场景的时长、字幕时轴和源片入/出点均来自数字人原声母版的实测时间，不使用脚本估时，也不对声音或嘴型做时间拉伸；
- 场景可在前端切换全屏数字人、左上角矩形画中画或暂时隐藏；全屏不再要求多余主体素材，画中画/隐藏继续复用现有网络、AI、人工和项目库素材来源；
- 可从实际版式生成首帧和高潮帧：画中画审核帧是真实的“主体画面 + 左上角数字人”合成，而不是两张孤立素材；
- 最终 FFmpeg 成片会保留母版的唯一原声音轨；数字人画中画素材被静音后叠加，避免双重对白；
- 已覆盖项目创建、素材包合同、原声时间线提交、全屏关键帧、画中画关键帧、画中画成片和普通工作台回归测试。

### 20.2 本次未承诺为已完成的能力

- **单轮数字人局部重组与 A/C 文件哈希证明**：当前可以替换某个 `Txxx` 原片，但需要重新核验、合成母版并重新应用时间线；这条路径是安全且可追溯的，但尚未做到只重新编码该轮次并自动拼接其余母版片段。
- **绿幕抠像、透明通道与圆角/阴影画中画**：界面会记录导出背景类型，P0 仅合成不透明矩形左上角画中画，绝不把未实现的抠像伪装为已完成。
- **云端供应商直接生成适配器**：阿里云等服务仍应先作为外部生成源导出后导入；提供方适配器是后续可插拔工作，不影响本地导入主路径。
- **真实浏览器端到端回归脚本**：本次完成了 API、状态和 FFmpeg 媒体级回归；下一阶段应加入 Playwright 覆盖创建、上传、应用时间线、切换版式和成片播放的完整用户旅程。
