# 每日科技快报工作合同

更新时间：2026-09-01

## 目标与流程

每天处理北京时间上一自然日 00:00—24:00 的科技新闻。代码负责热度观察、原文取证、聚类和硬门；豆包负责中国市场评分、中文双主持稿和独立冷审，Luna仅在豆包不可用时作可审计技术降级。栏目优先浏览热度、娱乐看点、画面感和科技新鲜度；通过结构与传播门后才进入媒体。

流程固定为：国内热度与候选→原文证据和代码硬门→豆包市场评分→Top 3 组合→冻结claim→豆包中文写稿→结构校验→豆包独立冷审→必要时定点返工。传播复验单独检查钩子、活人对话、信息维度、大众获得感和互动空间。

## 选题质量门

生产选择使用 H/C/U：H 是可观测热度，C 是可验证的独立事实容量，U 是大众理解成本；再结合编辑、大众和视觉潜力排序。程序约束 C，低价值候选只淘汰该条；首批不足继续从过门候选补位。只有穷尽候选后仍不足3条 C2 事件才停止文本生产；9个信息单元只是90秒规划目标。信息不足可自然缩短，禁止用参数或重复表述凑时长。入选后另算开场价值，大众可直接感知的热点优先首条；S/A/B 不控制句数。

热度采用“百度公开热榜快照 + 国内科技媒体直连 + Google 中文聚合补盲 + 可选抖音授权 API/离线快照”。抖音 API 必须使用 HTTPS Bearer，失败回落快照，两者都不可用则非致命跳过；不抓取受限页面，也不把热榜或第三方镜像当事实源。产品级热榜必须按实体匹配，Mac mini 的热度不得扩散给 Mac Studio 或通用 MINI 文案。

copy_skill 候选池按明确日期只读接入：从 current 校验 READY、日期及全量 manifest 哈希，禁止 latest 串日。条目只形成热度信号和 `discovery_only` 线索，可与媒体候选聚类但不算事实来源。必须保留 `partial` 警告、`not_checked` 和图片 `review_required`；无图不删题，输入无效则回落既有来源。

生产口径为“热点决定是否播，证据守住硬事实”。公开热榜有一条可读原文即可保留；平台已广泛传播且不改变事件本质的“破纪录、全球首个、超越人类”可作节目化称呼。诈骗指控、违法定性、SEO污染和无正文仍走硬风险门。至少一条公开热点入选；无热度的海外手机参数稿仅在强题不足3条时最多补1条。

Google News 标题摘要只算线索。入围候选须还原链接、抓原文并保存证据字段；公开热点至少一条正文，非热点强结论仍需官方或两家独立发布者，聚合转载不算独立来源。禁止用常识补齐骗局套路、玩家评价、产品效果或建议。

“怎么选、横向对比、购买建议、值不值得买、FAQ”等常青SEO导购稿不属于当日新闻事件，即使正文完整也必须单条淘汰，不能靠参数丰富或品类多样性进入整期组合。

需要解释两个以上陌生名词的题优先淘汰；单条最多保留一个英文专名，首次出现必须带中文通俗名称。

## 90 秒脚本合同

- 直接用中文构思中文稿，禁止先生成英文再翻译。T001 同时承担栏目身份、钩子和第一条正文，以“每日科技快讯来了”自然开场，紧接具体对象与利益、后果或反差。
- 台词槽数来自入选事件的冻结事实容量与必要解释槽，不按等级硬套句数。全片相邻台词严格换角色，跨新闻也不例外；除T001外每句都通过 `reply_to` 指向上一句，使双方承接关系可被审稿和后续时间线直接识别。
- 雅雅偏生活视角、具体追问、情绪和场景；檬檬偏事实、解释、边界和行业判断。两人都可说事实但不能复述，任一主播不得低于总字数30%。
- 普通台词建议14—42字，超过70字才视为异常；结尾建议18—42字，同样仅以70字作为异常保护。总口播建议365—420字，仅低于280字或超过600字才触发异常保护。建议区间只用于节奏优化，不得成为停机条件；是否拖沓主要由传播复验判断。H1补充新闻最多分配2个信息单元，只保留事件核心与最高价值差异，禁止用参数清单撑时长。

每句新闻台词必须声明独立 `information_key`，且 `information_dimension` 与冻结 claim 一致。相邻句必须切换信息维度；“文字不同、含义相同”仍视为重复。高热风险题优先覆盖具体事件、原理/套路、用户影响和有来源支持的行动提示，但不能为凑四要素编造事实。

每条 `stories` 必须声明 `event_identity`；首条前两句内、其余新闻第一句须说出公司+产品/模型或具体事件名。“顶级AI、某机器人、大厂动作”不算具体身份；自然口播可拆开主体与事件词，无需机械复读长标题。

檬檬必须自然接住上一句的具体对象或动作；雅雅正文追问最多三次且下一句必须直接回答。删掉任一主播后若理解和情绪几乎不受影响，就是凑句。“值得关注、拭目以待、科技圈炸锅、肉眼可见”等广播腔必须返工。`required_dialogue_move` 是语义动作，不是固定连接词；“具体看、而且、不过先别急、也就是说”等同一起句全稿最多一次，禁止模板轮换。

语气采用明快主持感：优先“没错、确实、精准、这也太狠了吧、太提气了”，情绪短语后必须继续提供信息；禁用“好家伙、撒胡椒面、牌桌加码、把筹码推上桌”等偏痞表达。每条一至两处即可，不能连续喊口号。

结尾只比较两条具有共同维度的新闻，禁止把三四件事硬串，也禁止只有标准答案的问题；必须允许观众分享真实行为或站队。

## 评分与事实边界

传播复验满分100：钩子20、活人对话20、信息密度25、大众价值20、互动15。含 H3/H4 时，85分且钩子/对话至少16、信息密度至少20标记 `auto_release`；最高仅H1/H2时，总分至少78、钩子至少14、对话至少15、信息密度至少19且硬门通过，可标记 `fallback_review_candidate`。后者只能生成醒目标记的待审视频，不得表述为优质稿或自动发布。低于门槛或命中事实、结构、预算红线仍为 `blocked`。视觉名场面、具体成绩和大众反差本身可构成公共价值。

公司人物、核心数字、价格日期、官方状态及法律安全结论必须来自冻结来源。节目表达允许常识性称呼、夸张形容、类比、吐槽、主观判断和带“未来/可能/如果”的展望，但不得伪造成新销量、能力或承诺。顺序版与角色纯净版必须逐字一致。

采用“事实层严谨、表达层放开、展望层标记”的边界：两成以上降价可说“大幅降低”，明确 AI 投入可说“大力支持/重押 AI”，牵头标准可说“提高国际话语权”；机器人做饭、收拾、陪护可以展望，但必须带“未来、可能、如果、真能”等标记。禁止把展望写成已有能力或承诺时间。

中转长文本使用SSE并按UTF-8解码；尾部中断仅有界重试，不跳过质量门。
文本恢复保存 Top 3 组合，全期最多两次独立传播复验。局部问题定点修稿、同质化换组合、超时长全局压缩；尝试耗尽后，最佳有效稿达到可靠线则转为 `fallback_review_candidate` 并继续待审媒体，仍低于可靠线才停在真实阻断状态。模型只写中文台词；确定性元数据修复不占复验次数。
`event_identity` 生成与验证共用判定器；纯时间和泛化趋势不得成为身份。确定性修复只改元数据，台词前后 SHA256 必须相同。相同组合、台词、元数据、错误和策略的拒稿不得重复计数；无进展依次升级到一次新鲜写稿和下一组合。
90秒是目标，预计超过120秒才确定性压缩；转场不得重复，连续技术名词清单必须改成类比或接梗。局部传播问题只返工点名台词，不因可确定修复的小措辞终止整期。

## 画面标题与音频合同

- 每条新闻必须有稳定 `story_id`，从脚本传播到场景和视觉块。同一新闻的所有台词共用一个右上角小标题，切到下一个 `story_id` 才替换；结尾不沿用新闻标题。
- 播出小标题由豆包基于已分配 `coverage_plan` 单独生成，不得直接复用媒体原题。代码必须拒绝claim之外的数字、纪录、涨幅、首发或开售状态；媒体原题只保留为 `source_headline` 审计字段。
- 一行标题仅用黄色；两行标题上白下黄，且黄色下行必须长于白色上行。固定位置在左上角数字人右侧，标题和逐句字幕是两套独立图层。
- 混合中英文标题不得拆开英文产品组合名；“下黄行更长”按实际视觉宽度判断，不按简单字符数判断，中文优先在产品名、动作或技术名词边界换行。
- 每日新闻的 HyperFrames 只负责主体信息图，不再烘焙右上角新闻标题；目标时长占比约30%—40%，其余优先使用匹配的网络视频；最终比例必须按已解析资产来源核验，不能采用计划路线字段。实拍约3秒一切（均衡槽2.2—3.5秒），HyperFrames单槽硬上限5秒；长台词必须拆成多个画面槽。同一网络素材全片只准使用一次，供应商ID、来源URL或资产ID重复均阻断 `review_ready`。
- 失败画面槽单独恢复，已完成槽不得重做。HyperFrames检查失败可回退未用网络素材；仅为修复最终比例且两轮严格审查失败时，才可用 `contextual_broll` 选择相关、非误导、全片唯一的环境补画面，并记录策略覆盖。
- 最终交付响度目标 -14 LUFS、True Peak 上限 -1.5 dBTP，质检容差为 -15.5 至 -12.5 LUFS且不得高于 -1.0 dBTP。未达标不得进入 `review_ready`。
- 项目级 `narration_policy.playback_gain_db` 独立于背景音乐，范围 -12—+12 dB、0.5 dB步进；新项目本机默认 +3 dB，历史项目保持原值。声音处理顺序固定为人物增益→背景音乐→最终 loudnorm；`audio_mix_signature` 同时覆盖人物和音乐设置，任一变化都会使旧声音样板和渲染衍生物失效，但不得重做或覆盖 Voicebox WAV、数字人原片和无音乐基线。

## 当前数字人结论

默认 RunningHub 为 `2094449979141218305` / `infinitetalk_448x560_exact_clock_v2`，使用同号 API JSON。最终角色 WAV 拼接后只做一次25FPS对齐并写节点35；短样本实测输入输出均4.720秒/118帧。

## 付费与前端边界

正式运行只有在文本双门通过后才可继续 Voicebox 与 RunningHub。全局默认 Standard 24GB（`instanceType=default`），不再以 Lite 为生产目标；Plus 48GB 仍禁止自动升级。每日总预算默认不超过5元，实际费率和费用必须写入付费账本。正式发布始终需要人工确认；失败从同日期运行清单恢复，已成功阶段不得重做。

人工确认的外部脚本可经确定性导入进入项目：必须保留逐字原文、绑定 `story_id`/新闻标题和来源记录，并将旧媒体阶段重置为待人工确认；旧 Voicebox 长音频只有“角色台词指纹和音色 ID”都匹配时才能复用，避免换稿串音。
